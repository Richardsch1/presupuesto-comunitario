# Seguridad y límites

Herramienta local sin cuentas, API remota, analítica o claves de servicio. Los archivos y las salidas pueden contener lo que la persona introduzca; no están cifrados. Revisa el contenido y sus permisos antes de compartirlo. Usa exclusivamente datos ficticios en demostraciones e issues.

Las validaciones y los patrones de revisión son limitados; no garantizan detectar toda información sensible ni certifican cumplimiento normativo. El equipo local, las copias de seguridad y otras aplicaciones quedan fuera de su control.

No publiques vulnerabilidades con datos privados. Si GitHub ofrece Report a vulnerability, úsalo; si no está habilitado, pide al mantenedor un canal privado sin exponer detalles sensibles. No se ofrece un plazo de respuesta. Revoca en el proveedor cualquier credencial expuesta.
